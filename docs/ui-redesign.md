# UI刷新と速度改善（2026-09-08再評価）

## 方針

シンプルで操作しやすい「Calm Utility」を基準にする。白い面と淡い背景、藍の主操作、細い境界線を使う。既存の暗いトップバーとURL、フォーム、デモ機能は維持する。

参考: [Refero](https://styles.refero.design/)、[Atlassianの余白設計](https://atlassian.design/foundations/spacing)、[Carbonのテーブル設計](https://carbondesignsystem.com/components/data-table/usage/)。外観の模写ではなく、情報の優先順位と操作の統一に用いる。

## 再調査の結論

配色の方向性は維持するが、前回の変更を「全体デザイン完成」とは扱わない。装飾の共通化より、用途別レイアウト、情報の見つけやすさ、不要な描画の削減を先に行う。

- [Middayの参照例](https://styles.refero.design/style/3f2b79c1-d980-4380-a903-29856975fc37)からは細い境界線と抑えた色数を参考にする。マーケティング用の大きなセリフ見出しや強い文字間隔を、日本語の記録・入力画面には持ち込まない。
- [GOV.UKのdetails指針](https://design-system.service.gov.uk/components/details/)に従い、折りたたみは補助情報に限定する。主要な登録操作や記録を隠すことを「シンプル化」としない。
- [Chart.jsの性能指針](https://www.chartjs.org/docs/latest/general/performance.html)を踏まえ、不要なアニメーションを外す。画面をSPA化する前に、現行構成での無駄な処理を測って減らす。

| 再調査で確認した点 | 判断・対応 |
| --- | --- |
| 汎用containerの960px化が認証・入力画面にも及ぶ | 汎用は従来の800px、明示した一覧だけ960px、カレンダー1280pxへ修正 |
| スマホで1個、PCで4個のグラフしか見えないが初期生成は双方8個 | 未表示canvasは展開・表示幅切替時まで生成しない |
| 折れ線を1点ずつ追加し、点数分updateする | 全日分を初回に描画。空データの目盛りも有限値へ補正 |
| 習慣・一時タスクの操作色が紫・明るい青に分散 | 操作の選択状態は藍へ。ユーザーのカテゴリ・予定ラベル色は維持 |
| 30px表示の共通ロゴが1,529,095 bytes | 次の最優先の配信量改善。現物の見た目を保つ最適化が必要で、今回は未変更 |

初回調査はローカルのデモ7画面を390pxと1440pxで表示し、リソースサイズとChart.jsインスタンス数を採取した。後続段階では専用の一時ユーザーで認証後ページとCRUDも検証した。実機Safariと管理者画面の実操作は未検証。

## 速度の確認値と残件

月表示の初期Chart.jsインスタンスはスマホ8→1、PC8→4。比較パネルは初期閉、未展開状態で測定した。展開済みインスタンスは再利用のため保持するので、すべて展開・幅切替した後も1個や4個という意味ではない。実環境のLCP・INP改善率は未計測。

[jQuery公式配信](https://releases.jquery.com/jquery/)の同一バージョンで、ファイル本体は288,580 bytesから89,501 bytesへ約69%削減。これは展開後ファイルサイズであり、圧縮転送量や表示時間が69%改善したという意味ではない。

開発配信でstyles.css 35,298 bytes、Chart.js 208,481 bytes、transaction.js 32,018 bytesにgzipとimmutableヘッダーが付くことを確認（展開後サイズ。最後の微修正前の測定）。圧縮率やページ速度の改善率を示す数値ではない。

残件:

1. 共通ロゴ・favicon・PWAアイコンの適正サイズ化。AI再描画ではなく通常の画像処理で見た目を保って圧縮する方針について確認中。元画像は未変更。

3. 本番反映は明示依頼と実行直前の承認を得た後に行う。特にNginxキャッシュと既存Service Worker更新を本番でも検証する。
